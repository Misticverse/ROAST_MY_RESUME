ROAST MY RESUME

A resume roast that makes you laugh.
Feedback that helps you improve.

Proof-of-concept product definition · Status: approved

THE ONE-PAGE JOURNEY

01 · StartOpen one page with a resume input and three result areas.
02 · PasteEnter resume text and submit it.
03 · ReviewGet a roast and all useful, distinct improvements when there is enough text.
04 · ImproveRead the feedback and use the suggested rewrites.

THREE PARTS, ONE RESUME

The Roast

Short, sarcastic, and playful—not cruel. It should respond to the submitted content without inventing resume details.

Real Talk

All distinct, actionable suggestions supported by a usable resume, prioritized by importance. Each item has a real quote and explanation; matching rewrites appear separately below. Missing facts become clear placeholders.

Rewrite

Matching suggestions appear here in the same order as Real Talk.

WHAT THE PAGE DOES IN EACH STATE

Before submission

The user can see where to paste text and where the roast and Real Talk results will appear.

Enough resume text

Show the short roast and all distinct, actionable, resume-grounded suggestions, with matching rewrites in a separate section.

Empty or fewer than five words

Show a more pointed roast about the missing or minimal input. Leave Real Talk and Rewrite empty and do not call the model.

Pasted-text handling

Show an accurate note explaining how pasted text is handled. Do not promise that it is not stored unless the implementation guarantees that.

HOW WE KNOW IT WORKS

  • Submitting a usable resume returns a roast and all distinct, actionable suggestions supported by its text, without a fixed three-item limit.
  • Each Real Talk suggestion quotes text from the resume and includes an explanation; its rewrite appears only in the separate Rewrite section.
  • No rewrite presents missing accomplishments or facts as true; a clear placeholder is used instead.
  • Empty input or fewer than five words shows only a roast and makes no model request.
  • The pasted-text note accurately describes what the app does.

KEEPING THE PROOF SMALL

One page. Text pasted by the user. One roast, all useful grounded suggestions, and a separate Rewrite section.

Accounts, saved profiles, file uploads, and persistent database storage are out of this proof of concept.

ONE DETAIL FOR THE TECHNICAL PLAN

The next planning step must establish what happens to pasted resume text so the privacy note can be truthful. Whether someone can edit and submit again during the same visit is a smaller behavior detail to settle during the build.
